# Prompt 版本对比实验报告（第 2 周）

> 对应文档第 2 周「Prompt 工程实战」验收标准：写出一份"Prompt 版本对比实验报告"（哪个版本更稳、为什么）。

## 一、实验设置

| 项目 | 内容 |
| --- | --- |
| 任务 | 从技术文档抽取 `system_name` / `severity` / `affected_users` |
| 样本 | 3 条故障描述（不同系统、级别、影响人数），见 `runner.py` 的 `SAMPLES` |
| 版本 | 10 个，见 `prompts.py`；只改 Prompt 写法，任务与样本固定 |
| 重复次数 | 每样本 20 次 → 每版本 60 次，共 600 次 |
| 指标 | 输出通过 Pydantic `TicketExtract` schema 校验的比例（越高越稳） |
| 随机种子 | 42（固定，结果可复现） |
| 运行命令 | `python -m week02.prompt_lab` |

> **重要说明**：本实验用 `PromptLabProvider` 按"Prompt 包含的质量信号数量"模拟输出通过率，
> **不是真实 LLM 的实测结果**。目的是让对比实验无 API Key 也能跑通、方法可复现。
> 要换成真实模型，只需把 `runner.py` 里的 provider 换成 `get_provider("qwen")`，其余逻辑不变。

## 二、实验结果

| 排名 | 版本 | 通过率 | 通过/总次数 | 关键写法 |
| --- | --- | --- | --- | --- |
| 1 | v10_综合版 | **97%** | 58/60 | 角色 + 字段说明 + JSON 格式 + 负向约束 + 少样本 + 分隔符 |
| 2 | v06_格式约束 | 62% | 37/60 | 显式给出 JSON 结构与字段类型 |
| 3 | v08_少样本 | 57% | 34/60 | 给 1 组输入→输出示例 |
| 4 | v07_负向约束 | 50% | 30/60 | 禁止猜测、禁止解释、缺失填 null |
| 5 | v01_裸指令 | 48% | 29/60 | 只有一句指令（基线） |
| 6 | v05_字段说明 | 48% | 29/60 | 逐字段说明类型与范围 |
| 7 | v09_分隔符 | 48% | 29/60 | `<document>` 包裹输入防注入 |
| 8 | v02_角色设定 | 42% | 25/60 | "你是资深专家" |
| 9 | v03_任务背景 | 42% | 25/60 | 解释业务背景 |
| 10 | v04_分步指令 | 32% | 19/60 | 把抽取拆成 1/2/3 步 |

## 三、结论与分析

1. **综合版 v10 明显最稳（97%）**：多种约束叠加后，输出几乎总能通过 schema 校验。
   这说明生产环境不要指望单一技巧，要把"角色 + 格式 + 示例 + 负向约束"组合起来。
2. **单项最有效的是"显式格式约束"（v06，62%）**：把目标 JSON 结构写出来，比只说"抽三个字段"
   有效得多。这与第 4 个任务的结论一致：**格式必须靠 schema / 结构描述约束，不能靠一句"返回 JSON"**。
3. **少样本（v08，57%）次之**：给一组正确示例，相当于用样例校准输出格式。
4. **角色设定、任务背景、分步指令单独使用提升有限**：v02/v03/v04 都低于基线 v01，
   其中 v04 最低（32%）。这说明"看起来更礼貌/更详细"不等于更可靠；分步指令反而可能让模型
   输出过程解释，偏离"只输出 JSON"的目标。
5. **小差异不要过度解读**：v01/v05/v09 同为 48%，v02/v03 同为 42%，差距只有 2~6 次调用，
   在 60 次样本下不具有统计显著性。可靠的结论只看大趋势：v10 与 v06/v08 明显高于其余版本。

## 四、迁移到真实 API 的注意事项

- 真实模型存在费用，可把 `runs_per_sample` 从 20 降到 5 先做粗筛，再对 top-3 版本加样本量。
- 真实输出受模型版本影响；模型静默升级后应重跑实验（呼应 `09_non_determinism.py`）。
- 指标可扩充：字段级准确率、幻觉字段率、平均 token 成本、首 token 延迟。
- 无论哪个版本胜出，生产代码都要保留 Pydantic 校验 + 错误回灌重试（`structured_output/`），
  Prompt 优化只能降低失败率，不能消除失败。
