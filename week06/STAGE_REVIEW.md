## 二、复盘模板四问（文档原文 + 填写示例）

### 1. 本阶段我独立完成了什么？

- **能 run 的**：P1 多模型网关 + FastAPI 服务 + Docker 编排；10+10+10 个按周组织的可运行样例。
- **有指标的**：100 请求压测对比表、令牌刷新次数（100 并发只刷 1 次）、19 字段审计、按 provider 成本日报、p95/429 比例。
- **能讲的**：三态熔断修正点、三层超时、可重试判据、幂等键构造、缓存命中与成本归因。

### 2. 哪些知识点我理解但用不出来？

- LangChain 的 LCEL 组合子会用，但还没在真实业务链里用过 `RunnableParallel` 的广播语义；
- RAG 的嵌入/重排指标只会背概念，没有亲手调过检索质量；
- 生产级 Redis 分布式锁只做了单进程 `asyncio.Lock` 版本，多实例场景还没落地。

→ **下阶段找机会用**：第 7~12 周把 RAG 全链路接进真实文档；第 13 周起用 Agent 编排时再练组合子。

### 3. 哪些我完全没搞懂？

- `TaskGroup` 与 `gather` 在嵌套取消场景下的精确语义；
- 分支覆盖率与行覆盖率在不同分支组合下的统计差异；
- 厂商流式接口的真实首 token 延迟受哪些网络因素支配（目前只有 Mock 数据）。

→ **标记**：面试前重点补前两项；第三项等拿到真实 Key 再做测量。

## 三、面试自述（脱稿练习稿）

1. **token 缓存策略**：access_token 不是 LLM 的分词 token；TTL 要留安全余量
   （`expireIn - 1000` 的思想），并发首次获取要单飞防击穿；Redis 与内存双后端接口一致。
2. **熔断降级链**：closed 全放行、failure_threshold 到阈值转 open、恢复窗口后只放 1 个探针、
   连续成功到阈值才 closed；open 期间降级链直接跳过该 provider，不浪费超时预算。
3. **成本核算模型**：成本 = 输入 token/1000 × 输入单价 + 输出 token/1000 × 输出单价；
   单价按 provider 从配置读，记录写在实际使用的模型上，再按天/场景聚合。
4. **与只会调 API 的区别**：统一抽象 + 配置路由 + 缓存 + 流式 + 并发控制 + 熔断降级 +
   重试幂等 + 全链路审计 + 成本日报 + HTTP/容器交付 + 单测门禁。
