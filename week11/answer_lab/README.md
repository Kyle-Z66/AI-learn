# 第 11 周 · 生成可靠性实验台（answer_lab）

> 目标：把"上下文不足会编造、引用会漂移、拒答是正确行为"从概念变成可运行、可断言的四类用例。
> 配套：[`week11/README.md`](../README.md) · 实测记录：[`REPORT.md`](REPORT.md)

## 一、这个实验台解决什么问题

第 7~10 周解决了"把正确片段找回来"，第 11 周回答"找到之后怎么可靠地写成答案"。
这里不接任何真实模型、不设 API Key：`FakeGenerator` 只把入选片段原文拼成带 `[n]` 的答案，
因此幻觉可以被精确注入、守卫可以被精确断言。真实项目只需把生成器换成 LLM 调用，
守卫与引用映射无需改动。

## 二、文件与数据流

| 文件 | 作用 |
| --- | --- |
| `cases.py` | 四类用例数据（相关 / 不相关 / 数字幻觉 / 实体幻觉）与篡改规则 |
| `__main__.py` | 运行器：组装 → 生成 → 篡改 → 组合守卫 → 判定；`self_check()` 供测试复用 |
| `README.md` | 本文件：用法、预期、边界 |
| `REPORT.md` | 本地真实运行输出抄录，含逐例结果与结论 |

```text
LabCase → build_context(预算+编号) → FakeGenerator.generate(带 [n])
        → case.tamper(注入幻觉值) → hallucination_guard(预检+后校验)
        → CaseResult(判定是否符合期望)
```

## 三、四类用例

| 类别 | 问题 | 注入 | 期望 |
| --- | --- | --- | --- |
| 相关 | 系统 cyclone 影响多少人？ | 无 | 放行，答案带 `[1][2]` 且可映射回原文 |
| 不相关 | 公司火星基地的预算是多少？ | 无 | 预检拒答，不编造 |
| 数字幻觉 | 系统 cyclone 影响多少人？ | `30 → 500` | 后校验失败项含 `500` |
| 实体幻觉 | 系统 cyclone 的负责人是谁？ | `张伟 → 李四` | 后校验失败项含 `李四` |

## 四、快速开始

```bash
# 仅验证导入与四类用例，不启动服务、不需要 Key
python -m week11.answer_lab
# 工程层全链路示范（预算截断 + 引用映射 + 篡改检测）
python -m week11.engineering.engineering_demo
# 单测
python -m pytest -q tests/week11
```

退出码：`0` 表示四类用例判定全部符合预期，`1` 表示有守卫失效或误拦。
输出中每条用例都打印答案、引用出处、拒答标志与失败项——失败项是可观测资产，
不是调试完就删的临时日志。

## 五、设计决策

| 决策 | 为什么这么选 | 代价 |
| --- | --- | --- |
| 用例数据化（LabCase） | 新增场景只加数据，运行器零改动 | 复杂场景需要扩展字段 |
| 篡改在生成之后 | 隔离"模型写错"与"上下文错了"，单独验证后校验 | 不覆盖检索错误场景（那是第 12 周） |
| 拒答也算用例结果 | 拒答率是健康指标，不能被当成失败吞掉 | 前端要单独处理 refused 分支 |
| 确定性 FakeLLM | CI 可精确断言每个 `[n]` 与失败项 | 不能代表真实模型的语言组织能力 |

## 六、Java → Python 思维差异

- Java 常用 enum + switch 分派场景；这里用 dataclass 数据驱动，新增场景不改控制流。
- Java 用 `Optional<T>` 表示"可能没有"；这里用 `refused: bool` + 固定拒答文案，
  业务层不必解包异常。
- Java 的 Mock 常随机造返回；这里用确定性拼装，测试可以逐字断言答案与引用。
